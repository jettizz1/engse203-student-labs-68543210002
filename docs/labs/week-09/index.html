01 · Data model

One requester, many requests

ข้อมูลผู้ใช้เก็บเพียงครั้งเดียว ส่วนแต่ละคำร้องอ้างถึงผู้ใช้ด้วย `requester_id` ที่มี foreign key คุ้มครอง

users

PARENT · 1
idINTEGER · primary key
nameชื่อผู้แจ้ง
departmentหน่วยงาน
emailUNIQUE · not null
1 → N
requester_id → id

requests

CHILD · N
idTEXT · e.g. REQ-001
requester_idINTEGER · foreign key
request_typeCHECK · allowed types
priority / statusdefaults + CHECK
การแยกตารางทำให้การแก้ชื่อผู้แจ้งแก้เพียงแถวเดียว ขณะที่ SQLite ปฏิเสธคำร้องที่อ้างถึงผู้ใช้ซึ่งไม่มีอยู่

02 · Query explorer

SQL you can run

เลือกหมวดเพื่อดูตัวอย่าง query จากไฟล์จริง ทั้งการค้นหา การ JOIN และการสรุปข้อมูล

ดาวน์โหลด queries.sql ↓
คำร้องที่ยัง pendingกรองสถานะพร้อมเรียงผลลัพธ์02
SELECT id, location, details, status
FROM requests
WHERE status = 'pending'
ORDER BY id;
กรองจากสถานะและเรียงตามรหัสคำร้อง
เร่งด่วนและยังไม่เสร็จเงื่อนไขสองข้อ · LIKE แบบบางส่วน03–04
SELECT id, location, priority, status
FROM requests
WHERE priority = 'urgent'
  AND status <> 'completed'
ORDER BY id;

SELECT id, details
FROM requests
WHERE details LIKE '%เครื่อง%'
ORDER BY id;
ตัวอย่างจากทั้งเงื่อนไขร่วมและการค้นข้อความ
คำร้องพร้อมชื่อผู้แจ้งJOIN ผ่าน foreign key05
SELECT r.id, u.name AS requester_name,
       r.request_type, r.status
FROM requests AS r
JOIN users AS u ON u.id = r.requester_id
ORDER BY r.id;
ผลลัพธ์มีชื่อผู้แจ้งโดยไม่ทำสำเนาชื่อใน requests
รายงานนับต่อผู้ใช้LEFT JOIN เก็บคนที่ยังไม่เคยแจ้งด้วย10
SELECT u.name, u.department, COUNT(r.id) AS total
FROM users AS u
LEFT JOIN requests AS r ON r.requester_id = u.id
GROUP BY u.id, u.name, u.department
ORDER BY total DESC, u.name;
ผู้ใช้ที่ยังไม่มีคำร้องจะปรากฏพร้อมยอด 0
คำร้อง 3 รายการล่าสุดเรียงเวลาใหม่ไปเก่าแล้วจำกัดผล08
SELECT id, request_type, created_at
FROM requests
ORDER BY created_at DESC, id DESC
LIMIT 3;
วันที่ sample ตั้งค่าคงที่เพื่อให้ผลทดสอบทำซ้ำได้
จำนวนคำร้องแยกตามสถานะGROUP BY + COUNT09
SELECT status, COUNT(*) AS total
FROM requests
GROUP BY status
ORDER BY total DESC, status;
สรุปทุกกลุ่มสถานะที่พบใน sample data

04 · Integrity checks

Invalid data is rejected

ทดสอบจริงด้วย SQLite และเปิดใช้ foreign key enforcement ก่อน insert

✓ Foreign key

ไม่รับ requester_id ที่ไม่มี

✓ CHECK

ไม่รับ status นอกชุดที่กำหนด

✓ UNIQUE

ไม่รับ email ซ้ำ

✓ Primary key

ไม่รับรหัสคำร้องซ้ำ

✓ NOT NULL

ไม่รับคำร้องที่ไม่มี location
