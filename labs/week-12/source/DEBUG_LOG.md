## BUG #0 · ค่าขอบรายละเอียด 10 ตัวอักษร (test เจอ — ไม่มีผู้ใช้แจ้ง)

- **อาการ:** ส่งรายละเอียด 10 ตัวอักษรพอดี ถูกปฏิเสธ ทั้งที่ข้อความบอกว่า "อย่างน้อย 10"
- **วิธีทำซ้ำ:** unit test `validateRequestInput({ ...valid, details: '1234567890' })`
- **เครื่องมือ:** unit test ค่าขอบ (TC-03) — fail ทันทีที่เขียน
- **สาเหตุ (ไฟล์:บรรทัด):** `api/src/validators/requestValidator.js` เงื่อนไข `length <= MIN_DETAILS`
- **วิธีแก้:** เปลี่ยนเป็น `length < MIN_DETAILS`
- **test ที่กัน:** `tests/unit/requestValidator.test.js` → "10 ตัวอักษร → ผ่าน (ตรงขอบพอดี)"

## BUG #1 · ลบคำร้องแล้วเพิ่มใหม่ ได้ 500

- **อาการ:** เมื่อลบคำร้องเดิมแล้วเพิ่มคำร้องใหม่ ระบบตอบกลับ HTTP 500 เนื่องจากสร้างรหัสคำร้องซ้ำกับรหัสที่มีอยู่ในฐานข้อมูล
- **วิธีทำซ้ำ:** 1 ลบคำร้อง REQ-002 ด้วย DELETE /api/requests/REQ-002 2 เพิ่มคำร้องใหม่ด้วย POST /api/requests พร้อมส่งข้อมูลคำร้องที่ถูกต้อง 3 ตรวจสอบผลลัพธ์ พบว่า API ตอบกลับ 500 แทน 201
- **เครื่องมือ:** ใช้ Terminal และ curl เพื่อทดสอบ API อ่าน Error Log ของ API และใช้ VS Code JavaScript Debug Terminal ตั้ง Breakpoint ในฟังก์ชัน nextId() เพื่อตรวจสอบค่าตัวแปรขณะทำงาน
- **สาเหตุ (ไฟล์:บรรทัด):** api/src/services/requestService.js ภายในฟังก์ชัน nextId() ใช้ SELECT COUNT(*) เพื่อนับจำนวนคำร้องที่มีอยู่ แล้วนำจำนวนดังกล่าวมาบวก 1 เพื่อสร้างรหัสใหม่ เมื่อมีการลบคำร้องตรงกลาง จำนวนรายการจะไม่ตรงกับหมายเลขรหัสสูงสุด ทำให้สร้างรหัสที่ซ้ำกับรายการเดิมและเกิดข้อผิดพลาด UNIQUE constraint
- **วิธีแก้:** แก้ฟังก์ชัน nextId() ให้ค้นหารหัสคำร้องล่าสุดด้วย ORDER BY id DESC LIMIT 1 แล้วนำหมายเลขรหัสสูงสุดมาบวก 1 หากยังไม่มีคำร้อง ให้เริ่มจาก REQ-001
- **test ที่กัน:** Integration test ใน tests/integration/requests.api.test.js ทดสอบลบ REQ-002 แล้วเพิ่มคำร้องใหม่ โดยคาดหวัง HTTP 201 และตรวจสอบว่ารหัสคำร้องทั้งหมดไม่ซ้ำกัน

## BUG #2 · Dashboard แสดง "กำลังดำเนินการ 0"

- **อาการ:** การ์ดสรุปจำนวนคำร้องสถานะกำลังดำเนินการแสดง 0 ทั้งที่ในรายการมีคำร้องสถานะ in-progress อยู่
- **วิธีทำซ้ำ:** 1 เปิดหน้า Dashboard ที่ http://localhost:5173 2 ตรวจสอบรายการคำร้องว่ามีสถานะ in-progress 3 เปรียบเทียบกับตัวเลขบนการ์ดสรุป พบว่าการ์ดกำลังดำเนินการแสดง 0
- **เครื่องมือ:** ใช้ Browser DevTools แท็บ Network ตรวจสอบ Response ของ GET /api/requests เพื่อยืนยันสถานะที่ API ส่งมา จากนั้นใช้แท็บ Sources และ Breakpoint ตรวจสอบการนับใน requestSummary.js
- **สาเหตุ (ไฟล์:บรรทัด):** frontend/src/utils/requestSummary.js ในฟังก์ชัน summarizeRequests() กำหนดให้ตัวนับ inProgress เปรียบเทียบกับข้อความ 'in progress' ซึ่งใช้เว้นวรรค แต่ API ส่งสถานะเป็น 'in-progress' ซึ่งใช้เครื่องหมายขีดกลาง ทำให้ไม่พบรายการที่ตรงกันและนับได้ 0
- **วิธีแก้:** แก้เงื่อนไขของตัวนับ in Progress ให้เปรียบเทียบกับ 'in-progress' ให้ตรงกับรูปแบบสถานะที่ API ส่งมา
- **test ที่กัน:** Unit test ใน frontend/src/utils/requestSummary.test.js สร้างข้อมูลจำลองที่มีสถานะ pending, in-progress และ completed แล้วตรวจสอบผลลัพธ์ที่คาดหวัง { total: 4, pending: 2, inProgress: 1, completed: 1 }

## BUG #3 · เปลี่ยนสถานะคำร้องที่ไม่มีอยู่ ได้ 500

- **อาการ:** เมื่อส่งคำขอเปลี่ยนสถานะของคำร้องที่ไม่มีอยู่ในระบบ API ตอบกลับ HTTP 500 แทน HTTP 404
- **วิธีทำซ้ำ:** ส่งคำขอ PUT /api/requests/REQ-999 พร้อม JSON { "status": "completed" } โดยใช้ curl แล้วตรวจสอบผลลัพธ์ พบว่า API ตอบกลับ 500
- **เครื่องมือ:** ใช้ Terminal ตรวจสอบ Stack Trace ของ API เพื่อระบุไฟล์และบรรทัดที่เกิดข้อผิดพลาด จากนั้นตรวจสอบลำดับคำสั่งใน requestController.js
- **สาเหตุ (ไฟล์:บรรทัด):** api/src/controllers/requestController.js บรรทัดที่ 30 ตามตัวอย่างในเอกสาร มีการเข้าถึง updated.id เพื่อบันทึก Log ก่อนตรวจสอบว่า updated เป็น null หรือไม่ เมื่อไม่พบคำร้อง การเข้าถึง .id ของค่า null จึงทำให้เกิด TypeError และ API ตอบกลับ 500
- **วิธีแก้:** ย้ายคำสั่ง console.log() ไปไว้หลังเงื่อนไข if (!updated) และให้ระบบส่ง HTTP 404 พร้อมข้อความแจ้งว่าไม่พบคำร้อง ก่อนเข้าถึงคุณสมบัติของ updated
- **test ที่กัน:** Integration test ใน tests/integration/requests.api.test.js ทดสอบเปลี่ยนสถานะคำร้อง REQ-999 และตรวจสอบว่า API ตอบกลับ HTTP 404 แทน HTTP 500
